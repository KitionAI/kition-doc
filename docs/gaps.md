# Gaps

> **Last updated:** 2026-11-28 · **Source:** `features.yaml` (updated 2026-11-28) and the engine's command list

Every known shortfall of Kition Doc, from the feature catalogue: features that are not yet `has`,
then the differences recorded on features that work. Update the feature in `features.yaml` when you
land work, then this list. The comparison with the target application is in
[parity/target-app-parity.md](parity/target-app-parity.md); the order of work is in [roadmap.md](roadmap.md).

## Features not done

- `doc.format.group-freeform` (P0, partial): Custom drawing paths survive import and save inside groups, and members keep their place in a group's own space. Formula coordinates and arc commands still require reference validation.
- `doc.layout.column-balance` (P0, partial): Columns before a continuous section break are balanced. Floating objects and footnotes inside balanced columns are not reference-checked.
- `doc.layout.content-control-marks` (P0, partial): Content controls make room for their start and end marks on their lines, as WPS lays them out. Content controls are not written back, so their marks are lost on save; controls around table rows and cells are not marked; the marks' metrics are measured from 10.5 to 40 pt only.
- `doc.layout.document-grid` (P0, partial): Section line grids control paragraph spacing and survive DOCX round trips. Character grids set East Asian characters in whole cells but don't snap Latin text or compress punctuation into them; exact glyph baseline parity still needs WPS corpus validation. A multiple whose text fits one row stays unrounded, as in WPS for Mac.
- `doc.layout.east-asian-font` (P0, partial): East Asian and Latin font slots are selected independently during shaping. Theme script mappings, legacy font charsets, the Times New Roman slot exception and matching reference fonts remain necessary for full fidelity.
- `doc.layout.east-asian-line-height` (P0, partial): Fonts for East Asian text use Word's East Asian single line height. Applies to the font that draws each run; Word's rule for East Asian characters drawn by a fallback font inside a Latin run, and remaining 8pt and large-multiple grid outliers in the WPS corpus, are not yet confirmed.
- `doc.layout.east-asian-spacing` (P0, partial): Mixed East Asian text honors automatic Latin and numeric spacing. Field boundaries, character grids and historical spacing compatibility flags still need reference validation.
- `doc.layout.eq-field` (P0, partial): Uncached EQ fields are drawn from their codes in each code run's formatting. Fractions, brackets, boxes, displacement, arrays, radicals and integrals are not yet compared with a reference; justified overstrike, Phonetic Guide alignments other than centred, line breaks between adjacent EQ fields, stacked superscripts and EQ fields nested in other fields remain incomplete.
- `doc.layout.field-tabs` (P0, partial): Field results honor paragraph tab stops, font runs and searchable leaders, hyperlink results keep their own formatting, and leaders fill as WPS fills them. Hyperlink results are not clickable, general field-result word wrapping and mixed-direction field flows still require reference validation.
- `doc.layout.float-position` (P0, partial): Floating objects mirror inside and outside placement on even pages, read alternate-content positions, wrap tightly along an object's wrap polygon, text boxes that fit their text are placed at its size, and text boxes that don't wrap keep long lines whole. Vertical inside and outside alignment, Word 2010 percentage positions (read from their absolute fallback, not computed), and wrap polygons of turned objects (their turned bounds are used) remain incomplete; polygons keep at most 32 points.
- `doc.layout.font-charset` (P0, partial): Font-table character sets guide missing-font substitution and round-trip safely. Embedded font tables, named character-set values, font family classifications, Panose matching and alternate names remain incomplete.
- `doc.layout.font-substitution` (P0, partial): Missing Latin families fall back to PingFang SC (Calibri and Aptos to Helvetica Neue after Carlito), missing Song, Ming, Hei, Kai and FangSong (宋体, 新細明體, 黑体, 楷体, 仿宋) families to an installed face of their style, and equation text falls back for letters its font lacks. Families WPS may lack but this machine has (Arial) and run font hints on ASCII punctuation are not yet compared; the line heights of the legacy macOS faces Helvetica, Courier and Monaco are not matched.
- `doc.layout.line-break-opportunities` (P0, partial): Lines break where WPS for Mac breaks them - not inside a word after a slash, question mark, exclamation mark or hyphen. Other punctuation inside Latin words matches the Unicode line breaking rules WPS was measured to follow; breaks at hyphens before digits and in East Asian runs are not reference-checked.
- `doc.layout.manual-run-width` (P0, partial): Manual run widths preserve contiguous formatting groups. Groups containing explicit controls or objects, inherited anonymous run boundaries, anonymous replica boundaries and exact WPS parity remain incomplete.
- `doc.layout.paragraph-spacing` (P0, partial): Adjacent paragraph spacing overlaps in body text and nested stories. Legacy automatic-spacing interactions, complex list boundaries and remaining WPS baseline differences still require reference validation.
- `doc.layout.punctuation-compression` (P0, partial): Enabled full-width punctuation compression participates in line breaking, and closing marks hang past the right margin. Opening brackets, quotation marks, Japanese kana compression and historical compatibility flags still need reference validation.
- `doc.layout.section-pages` (P0, partial): Section and page breaks start their pages as WPS does - no blank page for an empty section mark, no empty line after a paragraph-ending page break, and blank even or odd filler pages without headers or footers. Whether Word (rather than WPS) shows headers on inserted blank pages is not reference-checked.
- `doc.layout.theme-fonts` (P0, partial): Theme-only font references select language-specific and regional theme faces. Unlisted locale mappings, explicit cached-name priority and re-resolving script references after theme edits remain incomplete.
- `doc.layout.two-lines` (P0, partial): Combined text uses two editable sub-rows in one logical line. Enclosing brackets, rotated or bidirectional groups, explicit controls/objects, simultaneous manual widths, inherited anonymous and replica boundaries, and exact WPS parity remain incomplete.
- `doc.lists.chinese-numbering` (P0, partial): Chinese counting, legal and enclosed-circle list numbering. WPS references only show values up to three; forms above ten follow standard Chinese numerals, unconfirmed against a reference. Other ECMA-376 number formats still read as decimal and save as decimal.
- `doc.render.character-scale` (P0, partial): Character width scales glyph outlines in raster and selectable PDF output. Manual fitText widths, combined East Asian runs and exact WPS raster parity remain incomplete.
- `doc.render.custom-curves` (P0, partial): Custom Bezier curves keep their control points in raster output and DOCX saves. Formula coordinates and arc commands still require reference validation.
- `doc.render.custom-path-paints` (P0, partial): Custom paths retain independent fills and strokes and compound contour winding. Formula coordinates and arc commands still require reference validation.

- `doc.drawing.blurred-group` (P1, partial): A group holding a blurred shadow, a glow or soft edges prints its text as ink, as WPS prints such a group as one picture. The group is still drawn as vectors (WPS rasterises it), only the effects Kition Doc reads (outer shadow, glow, soft edges) count, and whether WPS also flattens a lone shape with a blurred effect is not reference-checked.
- `doc.drawing.objects` (P1, partial): Drawing objects: insert, transform, format, connect, group, arrange; ink. Engine tests run these commands, but no case shows them working in the editor and surviving save and reopen.
- `doc.drawing.picture-adjust` (P1, partial): Pictures are drawn with their colour adjustments (brightness, contrast, washout, grey scale, black and white, opacity). Other blip effects (recolour, duotone, artistic effects) and VML picture gain and black level are not applied; brightness and contrast follow WPS's printed pictures, but how brightness combines with more contrast is not reference-checked.
- `doc.drawing.picture-shape` (P1, partial): Pictures cut to a preset outline (an ellipse, a rounded rectangle, an arrow...) are drawn cut to it, with their line, shadow and glow, and keep them through saves. Vector pictures (SVG, metafiles) are not cut, custom outlines (a:custGeom), dashed lines, soft edges, inner shadows, reflections and 3-D rotation are not drawn, a picture that may have see-through pixels casts no shadow or glow (WPS's follow its pixels), and the drawing tools cannot set an outline yet.
- `doc.drawing.smart-graphic` (P1, partial): Smart graphics are drawn from their stored drawing with the shared preset outlines and placeholder prompts. The diagram layout is not run (the stored drawing is the picture), text turned other than level is drawn level, gradients show their first stop, and the reader lives in Kition Doc rather than the drawing crate the kits share.
- `doc.drawing.vml-art-text` (P1, partial): VML art text (text watermarks) is drawn as its string stretched to its shape and written back as VML. Only plain stretched text paths are drawn (no VML text path shapes other than the plain one), the fill's opacity is shown over a white page, and picture watermarks' washout is not applied.
- `doc.drawing.vml-shape-line` (P1, partial): VML shapes and text boxes take their line from their v:stroke element, as WPS draws them. Dash styles, line joins and VML's default fill for shapes that name none are not read, and a shape with neither a stroked attribute nor a v:stroke element draws no line.

## Differences on working features

- `doc.agent.guard`: Independent comparison retains conservative family holds. Comment reports include detached threads, and destructive writes must hold the content and metadata they discard. Private geometry facts are eager. Existing saved-file identity and convergence limitations remain documented in agent/guide.md.
- `doc.editor.keyboard-and-zoom`: Checked in the development host only (Kition Desktop's keyboard on opening is the host's). The zoom percentage counts CSS pixels per point, so the page opens at 133% (WPS's 100% is a CSS pixel per point); showing the opening size as 100% waits for a maintainer, as the page-view tests assert 133%. A page the caret goes to comes into view, not yet the caret's line (stage 0B). Show/Hide ¶ turns over but no marks are drawn (stage 6A); Cmd+K and Go To open the generic parameters (stage 6A).
- `doc.editor.system-clipboard`: A copy puts plain text only (the HTML comes with the engine's answer in stage 0B); Paste Special opens the generic parameters; copying between real applications, and in Kition Desktop's frame, is for a person to confirm.
- `doc.format.character`: Save and reopen as .docx is proven by command for bold, italic, underline, strikethrough, size, font, highlight, superscript and colour; the feature's other commands are covered by engine tests only.
- `doc.format.paragraph`: Save and reopen as .docx is proven by command for alignment, indent and line spacing; the feature's other commands are covered by engine tests only.
- `doc.headers.footers`: Save and reopen as .docx is proven by command for header text and a page-number footer; the feature's other commands are covered by engine tests only.
- `doc.layout.page-setup`: Save and reopen as .docx is proven by command for page size, orientation, margins and columns; the feature's other commands are covered by engine tests only. page.hyphenation sets the document's automatic hyphenation, which is saved but, as in WPS for Mac, doesn't break words.
- `doc.lists.bullets-numbering`: Save and reopen as .docx is proven by command for bullets, numbering and list levels; the feature's other commands are covered by engine tests only.
- `doc.security.workspace`: Links a document holds (external pictures, templates, data sources, INCLUDETEXT and the other fields) are never read and stay as data, but no check code reports them yet.
- `doc.styles.manage`: Save and reopen as .docx is proven by command for applying Heading 1, Heading 2 and a named style (Quote); the feature's other commands are covered by engine tests only.
- `doc.tables.edit`: Save and reopen as .docx is proven by command for inserting a table, typing in cells, inserting rows and columns, and cell formatting; the feature's other commands are covered by engine tests only.
- `doc.text.typing`: Save and reopen as .docx is proven by command for typing, tabs, line breaks, new paragraphs and page breaks; the feature's other commands are covered by engine tests only.
